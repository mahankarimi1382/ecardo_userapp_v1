# eCardo Dead CTA, Mock Data & Raw Error Verification Matrix

**Document Version:** 2.0  
**Audit Date:** 2026-10-20  
**Scope:** Static analysis, AST inspection, and runtime trace verification across all 137 routes and presentation screens in `ecardo_userapp_v1` (Flutter 3.44.6 / Dart 3.12.2).  
**Target Repository Commit:** `54ce4252080cc5569760c8a6e3181d7785c22af2`

---

## 1. Executive Summary

This audit verifies earlier findings (`AUD-001` through `AUD-008` from `docs/uiux/DEAD_CTA_MOCK_AUDIT.md`) against the actual codebase, and performs a comprehensive inspection of all empty event handlers (`onPressed: () {}`, `onTap: () {}`), null handlers (`onPressed: null`, `onTap: null`), "coming soon" toasts, TODO/FIXME comments, and mock data leaks in the presentation layer.

Key takeaways:
- Earlier findings `AUD-001` through `AUD-008` have indeed been addressed in code, with `AUD-003` retaining a fallback rate (`95000.0`) when live streaming rates are unavailable.
- Two explicit empty handlers exist in production screens (`CTA-001` in the end-drawer biometric switch row, and `CTA-002` in the flight details outbound offer card).
- Four travel sub-modules (`Boat`, `Dining`, `Local Experience`, and `Insurance Claims`) operate on local mock data simulation because backend endpoints on `trip.ecardo.ir` are pending.
- 44 route constants registered in `routes_handler.dart` are bypassed in the UI by direct `Get.to(() => Screen())` closures, creating untracked navigation paths.
