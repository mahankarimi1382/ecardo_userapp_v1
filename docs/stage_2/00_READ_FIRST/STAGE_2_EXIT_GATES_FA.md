# دروازه‌های خروج مرحلهٔ ۲

## Gate A — هم‌خوانی ورودی‌ها
- [ ] SHA فعلی checkout ثبت شده است.
- [ ] خروجی مرحلهٔ ۱ متعلق به همین SHA یا به‌صورت مستند reconcile شده است.
- [ ] تفاوت candidate routeها و routeهای confirmed مشخص است.
- [ ] فایل‌ها، تست‌ها و محدودیت‌های موجود قبل از هر تغییر ثبت شده‌اند.

## Gate B — قراردادها
- [ ] قراردادهای هر ماژول با کد Dart و قرارداد backend واقعی تطبیق داده شده‌اند.
- [ ] مالک منبع حقیقت برای مبلغ، موجودی، نرخ، کارمزد، وضعیت و دسترسی مشخص است.
- [ ] schema فیلدهای اجباری/اختیاری، واحدها، nullability، enumهای وضعیت و خطاها مشخص است.
- [ ] تفاوت محیط‌ها، API version و fallbackها ثبت شده‌اند.
- [ ] قراردادهای حدسی یا فاقد backend evidence همچنان `UNCONFIRMED` هستند.

## Gate C — ریسک‌های P0/P1
- [ ] تمام یافته‌ها دارای مسیر فایل/endpoint یا مدرک هستند.
- [ ] P0ها یا اصلاح و با تست اثبات شده‌اند یا مهار/متوقف و با blocker روشن ثبت شده‌اند.
- [ ] P1ها مرتب شده و اثر و معیار پذیرش دارند.
- [ ] تست تکرار درخواست، وضعیت نامعلوم پس از timeout، مبلغ/واحد، کارمزد، وضعیت تراکنش و مجوز بررسی شده است.
- [ ] هیچ عملیات مالی واقعی انجام نشده است.

## Gate D — اصلاحات مرحله‌ای
- [ ] هر تغییر به Issue ID + Route/Flow ID + Contract ID وصل است.
- [ ] diff از نظر scope و فایل‌های مالکیت‌قفل بررسی شده است.
- [ ] تست‌های مربوطه وجود دارند؛ PASS بدون شواهد ممنوع است.
- [ ] خطا، loading، empty، offline و status ambiguity برای flowهای اصلاح‌شده بازبینی شده‌اند.

## Gate E — تحویل
- [ ] `docs/integration/CONTRACT_REGISTRY.csv` به‌روز است.
- [ ] `docs/integration/ISSUE_REGISTER.csv` و `P0_P1_REMEDIATION_REPORT.md` تکمیل شده‌اند.
- [ ] `docs/integration/TEST_EVIDENCE.csv` شامل خروجی واقعی است.
- [ ] coverage از روی catalog واقعی محاسبه شده؛ درصد حدسی گزارش نشده است.
- [ ] `graphify update .` اجرا شده یا وضعیت گراف stale مستند شده است.
- [ ] هیچ push/release/deploy انجام نشده است.

**مرحلهٔ ۲ با «تعداد تسک‌های بسته‌شده» به‌تنهایی قبول نمی‌شود؛ Gateهای بالا باید پاس شوند یا موارد BLOCKED با ریسک، دلیل و مالک مشخص تحویل داده شوند.**
