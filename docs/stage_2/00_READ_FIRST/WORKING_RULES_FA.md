# قوانین اجرای مرحلهٔ ۲

1. checkout واقعی و SHA آن را ثبت کن؛ خروجی‌های مرحلهٔ ۱ باید متعلق به همین checkout باشند.
2. قبل از جست‌وجوی گسترده در سورس، مطابق راهنمای پروژه `graphify query "trace all critical eCardo flows and their controller service API data dependencies"` را اجرا کن. اگر دستور/ابزار در دسترس نیست، blocker را مستند کن؛ دستور جایگزین را از راهنمای محلی پیدا کن و وانمود نکن Graphify اجرا شده است.
3. `git checkout`, `git stash`, `git reset --hard`, `git clean` یا حذف/بازنویسی تغییرات موجود ممنوع است.
4. baseline و diff را فقط‌خواندنی ثبت کن؛ فایل‌های دیگران یا sessionهای موازی را دستکاری نکن.
5. فایل‌های قفل‌شده/اشتراکی `app_colors.dart`, `app_spacing.dart`, `light_theme.dart`, `dark_theme.dart` و `common/widgets/design_system/**` را بدون مالکیت صریح تغییر نده.
6. تغییرات theme یا API مشترک را در چند agent موازی ننویس. یک integrator برای قراردادها و merge تصمیم نهایی دارد.
7. هیچ agent موازی `flutter test` اجرا نکند؛ اجرای نهایی تست‌های موردنیاز سریال و تحت مسئولیت integrator باشد. هر agent می‌تواند فقط تحلیل ایستا روی فایل‌های خودش انجام دهد، اگر با قوانین repo مجاز باشد.
8. عملیات پرداخت، انتقال، صدور کارت، برداشت، webhook واقعی یا هر کار غیرقابل‌بازگشت ممنوع است. فقط mock/sandbox و حساب تست مجاز است.
9. هیچ PII، token، seed phrase، password یا key در گزارش، log، CSV یا screenshot ذخیره نشود.
10. از `double` برای مبلغ/نرخ مالی استفاده نکن؛ نوع داده و واحد مبلغ را از قرارداد واقعی مشخص کن و تبدیل را با decimal/integer minor units امن انجام بده.
11. retry خودکار عملیات مالی غیر idempotent ممنوع است مگر قرارداد backend و کلید idempotency آن اثبات شده باشد.
12. UI نباید منبع حقیقت برای موجودی، کارمزد، صلاحیت کاربر یا وضعیت نهایی تراکنش باشد؛ تصمیم و وضعیت مالی از backend معتبر پیروی می‌کند.
13. از GetX/Dio و معماری فعلی فقط وقتی شواهدی از مشکل یا نیاز واقعی هست فاصله بگیر؛ مهاجرت سراسری صرفاً برای سلیقه مجاز نیست.
14. `graphify update .` را پس از تغییرات در صورت پشتیبانی دستور و اجازهٔ repo اجرا کن؛ اگر نه، خروجی Graphify را به‌عنوان stale علامت بزن.
15. هیچ push, tag, release, deploy یا تغییر remote بدون اجازهٔ صریح انجام نده.
16. هر PASS باید به شناسهٔ تست/شاهد واقعی پیوند داشته باشد. در غیر این صورت `NOT_VERIFIED`, `BLOCKED` یا `FAIL` ثبت کن.
