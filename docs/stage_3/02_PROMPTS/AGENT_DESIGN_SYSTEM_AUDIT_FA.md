# عامل A — Design System Audit

از Design System Guide و تمام token/componentهای واقعی شروع کن. فهرست componentهای موجود، usages، variantها، visual drift، duplicate implementation، قابلیت‌های inaccessible و رفتارهای خطرناک را ثبت کن. به‌خصوص actionهای no-op، swipeهای controlled/reset، default success رسید و empty-stateهای بدون callback را جست‌وجو کن. بدون هماهنگی فایل‌های قفل‌شده را دست نزن. خروجی: audit، adoption matrix پیشنهادی، ADR برای تغییرهای عمومی و patch محدود با مالکیت انحصاری.
