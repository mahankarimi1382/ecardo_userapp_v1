# قوانین اجرا و تقسیم مالکیت

1. تغییرات موجود در working tree را متعلق به خود فرض نکنید. پیش از شروع، وضعیت را ثبت کنید.
2. `git checkout`، `git stash`، `git reset --hard` و حذف فایل/تغییر ناشناس ممنوع است.
3. قراردادها را قبل از تغییر UI بشناسید. هیچ fallback بصری نباید نتیجهٔ مالی ساختگی تولید کند.
4. فایل‌های Design System که در `DESIGN_SYSTEM_GUIDE.md` قفل شده‌اند فقط با هماهنگی مالک تعیین‌شده تغییر می‌کنند.
5. هر فایل مشترک یک owner داشته باشد. چند agent روی یک فایل مشترک و یک زمان کار نکنند.
6. ایجنت‌های تخصصی گزارش و patch پیشنهاد می‌دهند؛ Integrator تغییرات را ادغام و تست نهایی را سریال اجرا می‌کند.
7. اگر تست fail شد، نقص را ثبت کنید؛ تست را تغییر ندهید تا صرفاً سبز شود.
8. dependency فقط با ADR، بررسی مجوز، نگهداری، API، سازگاری و benefit قابل‌اندازه‌گیری اضافه شود.
9. screenshotها نباید token، اطلاعات شخصی، شمارهٔ کارت/حساب یا دادهٔ واقعی را نمایش دهند.
10. هیچ Push/Release/Deploy انجام نشود.
