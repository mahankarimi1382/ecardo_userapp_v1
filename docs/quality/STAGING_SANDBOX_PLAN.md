# طرح محیط Staging/Sandbox بک‌اند — باز کردن MP-110/MP-111/MP-015A

- **تاریخ:** 2026-10-24 · **وضعیت:** پیشنهادی — منتظر تأیید و اجرای صاحب پروژه روی سرور
- **قید حاکم:** قانون ۱ AGENTS.md — هر اجرای سرویس production/staging فقط روی سرور (serv.interex.ir / 192.168.100.65)، هرگز روی PC شخصی. این سند فقط چک‌لیست اجراست.

## هدف

تست‌های قراردادی و یکپارچگی (MP-110)، تست‌های authorization منفی (MP-111) و اسکرین‌شات/ران‌تایم اپ (MP-015A) به محیط اجرای PHP + دیتابیس + credential تست نیاز دارند. هیچ سکرتی در مستندات یا ریپو کپی نمی‌شود (قاعدهٔ MP-007).

## گام‌های پیشنهادی روی سرور

1. **ایزوله‌سازی:** یک دایرکتوری مستقل staging (مثلاً `/opt/ecardo-staging`) با clone بک‌اند از مخزن/باندل سرور؛ **جدول‌های جدا یا دیتابیس جدا** (`ecardo_staging`) — هرگز روی دیتابیس production.
2. **وابستگی‌ها:** `composer install --no-dev` نسخهٔ سرور + PHP 8.3+ و اکستنشن‌ها؛ فایل `.env.staging` فقط روی سرور ساخته شود با: `APP_ENV=staging`، `APP_DEBUG=false`، دیتابیس staging، `INTERNAL_NOTIFY_SECRET` و `TRAVEL_INTERNAL_SECRET` مقدارهای تصادفی (بستن SEC-5 در staging)، سکرت‌های `IPN_SECRET_*` برای درگاه‌های تست (بستن SEC-2/SEC-3).
3. **seed دادهٔ تست:** اجرای seederهای دمو (`DemoAccountSeeder` — حساب‌های demo@ecardo.test با پسورد شناخته‌شدهٔ تست) + کاربران نقش‌دار برای تست‌های authorization منفی (کاربر عادی/مسدود/بدون KYC).
4. **درگاه پرداخت آزمایشی:** فعال‌سازی `GatewaySandbox` **فقط در APP_ENV=staging** (پس از اعمال گارد GAP-007) برای شبیه‌سازی موفق/ناموفق بدون پول واقعی.
5. **دسترسی از اپ:** یک build flavor/staging-pointing برای userapp که baseUrl را به staging می‌برد (تغییر کد کلاینت لازم است — تسک جداگانه) یا اسکن route با curl/HTTPie به‌جای اپ.
6. **اجرای تست‌ها:** `php artisan test --env=staging tests/Feature/Api` شامل `HighRiskRoutesTest` (نقطهٔ شروع MP-111) و تست‌های قراردادی MP-110، سریال توسط Integrator.
7. **شواهد:** خروجی تست‌ها و لاگ‌ها به `docs/quality/TEST_EVIDENCE.csv` ریپو منتقل شود (بدون سکرت)؛ SHA سرور و دیتابیس ثبت شود.

## پرسش‌های اجرایی برای صاحب پروژه

- فضای دیسک/منابع سرور برای دیتابیس دوم کافی است؟
- clone بک‌اند روی سرور از کجا؟ (ریپوی محلی به GitHub وصل نیست — انتقال باندل یا mirror خصوصی)
- آیا دامنه/پورت staging از بیرون لازم است (برای اپ موبایل) یا فقط داخل شبکهٔ سرور کافی است؟
